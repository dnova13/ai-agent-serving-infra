| 결과 | 결론 |

- 주의: Day 9 의 "택배 언제 와요?" 처럼 점수가 높은데 틀린 top-1(0.7359)은 threshold 로 못 거른다. `source` 필터 등 다른 방법이 필요하다.

확인된 것:
- 에이전트가 실제 Qdrant 문서를 근거로 답한다. 환불 답변에 mock 에는 없던 "왕복 배송비 고객 부담", "30일 이내"가 나왔다. 채팅 모델 호출은 2번(도구 호출 결정 + 최종 답변)이다.
- 도구 선택이 올바르다. 인사는 도구 없이, 시간은 `get_current_time`, 정책 질문은 검색.
- 문서에 없는 질문에서 환각 없이 모른다고 답했다. `RAG_RULE` 효과.

시간은 2.8초~21.7초로 크게 튄다. 호출 수는 같은 케이스(예: 인사 1회 20초, 제주 2회 2.8초)에서도 반대로 나와서 호출 수가 원인이 아니고, 무료 Gemini 의 호출 편차다. 이 편차가 k6 전에 fake-LLM 모드가 필요한 이유다.

### 강제실패 FAIL 원인

버그가 아니라 테스트 문구 문제다.
- `search_vector_db` 는 모델이 넘긴 **검색어**에 `강제실패` 가 들어 있을 때만 예외를 던진다.
- 질문 뒤에 "(검색 키워드: 강제실패)" 를 붙이면 모델이 검색어를 "환불 정책" 으로 정리해서 넘겨 실패가 일어나지 않았다. 그래서 `retry=0` 이고 정상 답변이 나왔다.
- 조치: 질문을 "강제실패 라는 키워드로 검색해서 알려줘" 로 바꿨다. 이래도 모델 판단에 따라 달라질 수 있어, 확실히 보려면 도구를 직접 호출하는 단위 테스트가 더 낫다.

### 결과 상세 해설 (처음 보는 사람용)

**점수는 무엇인가**
- 질문을 벡터로 바꿔 저장된 문서 24개와 얼마나 비슷한지 잰 값이다. 1에 가까울수록 비슷하다.
- Qdrant 는 아무리 엉뚱한 질문이어도 가장 비슷한 문서를 반드시 하나 돌려준다. "없음"이라고 말하지 않는다. 그래서 세종대왕 질문에도 리뷰 문서가 1등으로 나온다(0.56). 이 문서를 모델에 넘기면 쓸데없는 근거가 섞이므로 "점수가 일정 이하면 버리는 기준"을 찾으려고 측정했다.

**세 구간이 의미하는 것**

| 구간 | 점수 | 의미 |
| --- | --- | --- |
| 관련 질문 | 0.72~0.81 | 정답 문서를 제대로 찾음 |
| 쇼핑몰 질문, 문서에 없음 | 0.65~0.70 | 배송, 환불 같은 쇼핑몰 용어가 비슷해서 중간 점수 (예: "해외 배송도 되나요?" -> ship-001 0.7003) |
| 완전 무관 | 0.55~0.62 | 쇼핑몰과 상관없음 |

- 0.65 를 기준으로 하면 완전 무관한 질문은 걸러진다. 간격이 0.1 이다.
- "문서에 없는 쇼핑몰 질문"은 관련 질문과 0.02 차이라 점수로 못 가른다. 이 구간은 프롬프트 규칙(`RAG_RULE`, 시스템 프롬프트)이 맡는다.

**에이전트 통합 테스트를 읽는 법**
- 일반 상식으로는 나올 수 없는 값(왕복 배송비 고객 부담, 30일, 5만 원, 100만 원)이 답변에 나왔다. 모델이 지어낸 말이면 이렇게 맞을 수 없으므로 문서를 읽고 답했다는 증거다.
- 모델 호출이 2번인 이유: 첫 호출에서 "검색이 필요하다"고 결정하고, 검색 결과를 받은 두 번째 호출에서 최종 답변을 쓴다. 인사는 검색이 필요 없어 1번이다.
- 문서에 없는 "포인트 적립률"은 숫자를 지어내지 않고 정보가 없다고 답했다.
- 시간(2.8초~21.7초)이 들쭉날쭉한 것은 호출 수와 무관하다(1번인 인사가 20초, 2번인 제주 질문이 2.8초). 무료 Gemini 의 응답 편차이며, k6 전에 fake-LLM 지연 모드가 필요한 이유다.

**각 실험이 답하는 질문**

| 실험 | 답하는 질문 | 못 답하는 질문 |
| --- | --- | --- |
| `score_noise` | 검색 점수로 무관한 질문을 거를 수 있나 | 모델이 실제로 뭐라고 답하나 (모델을 부르지 않음) |
| `agent_e2e` | 에이전트가 도구를 고르고 문서를 근거로 답하나 | 범위 밖 질문은 처음에 케이스가 없어서 못 봄 -> 아래 발견 |

### 발견 — 범위 밖 질문에 에이전트가 일반 상식으로 답함

`score_noise` 는 검색 점수만 쟀고 채팅 모델은 부르지 않아서 무관한 질문의 답변은 확인하지 못했다. 에이전트에 직접 물어 확인했다.

| 질문 | 도구 호출 | 답변 (시스템 프롬프트 추가 전) |
| --- | --- | --- |
| 세종대왕이 누구야? | 없음 | 조선 4대 왕, 훈민정음 창제 등 업적을 길게 설명 |
| 점심 메뉴 추천해줘 | 없음 | 한식, 양식 등 메뉴를 카테고리별로 추천 |

| 항목 | 내용 |
| --- | --- |
| 원인 | `agent_node` 가 사용자 질문만 모델에 넘기고 시스템 프롬프트가 없었다. 도구는 선택 사항일 뿐 역할 제한이 아니라서, 모델이 "검색 불필요"로 판단한 질문은 자기 지식으로 답한다 |
| 왜 threshold 로 안 되나 | `score_threshold` 는 검색이 일어난 뒤에 작동한다. 모델이 검색을 아예 부르지 않는 이 경우에는 효과가 없다 |
| 위험 | 범위 밖 질문에 토큰 낭비. 정책 질문도 검색을 건너뛰고 모델 추측으로 답할 수 있음(지금까지는 모델이 검색을 택했을 뿐 보장이 아님) |
| `/rag/ask` 는 | 항상 검색하고 `RAG_RULE` 이 있어서 문서 밖이면 "문서에 해당 내용이 없습니다"로 답한다. 에이전트에는 이 규칙이 없었다 |

조치 (`agent_graph.py`):
- `SYSTEM_PROMPT` 상수 추가. 쇼핑몰 상담원 역할, 정책 질문은 검색 결과만 근거로 답하고 없으면 모른다고 답하기, 시간은 도구로 확인, 쇼핑몰과 무관한 질문은 거절 안내.
- `agent_node` 에서 모델 호출 직전에 `[SystemMessage(SYSTEM_PROMPT)] + state["messages"]` 로 붙인다. state 에는 넣지 않는다. 기존 호출은 `[OLD]` 주석으로 남김.
- `agent_e2e` 에 "범위밖-역사", "범위밖-점심" 케이스 추가 (기대: 도구 없이 거절 안내).

한계: 프롬프트는 강제가 아니라 유도라서 100% 보장은 아니다. 변경 후 `agent_e2e` 를 다시 돌려 기존 케이스가 깨지지 않았는지(특히 인사, 시간, 정책 질문의 검색 호출 유지) 확인해야 한다.

## 대화로 정리한 내용

Day 11 은 새 기능을 만드는 날이 아니라 Day 10 에서 만든 RAG 에이전트가 믿을 만한지 확인하는 날이었다. 이 프로젝트의 핵심은 느리고 불안정한 AI 호출을 Kafka, Redis, Qdrant 로 제어하고 k6 로 동기와 비동기를 비교하는 것이다. RAG 에이전트는 그 부하 테스트의 대상일 뿐이라서, 실험에 들어가기 전에 "정상적으로 동작한다"는 기준선만 확인하면 된다. 같은 이유로 `score_threshold` 는 지금 정하지 않아도 프로젝트에 영향이 없어서 수치만 기록해 두기로 했고, Day 12 의 Chunking 실험도 RAG 품질 쪽이라 핵심과는 거리가 있다. 10월 전체 범위 일정을 생각하면 Day 12 는 간단히 하고 Kafka, WAS 로 빨리 넘어가는 방법도 있어서, 일정표를 보고 정하기로 했다.

결과를 풀어서 보면 이렇다. 검색 점수는 질문과 문서의 유사도인데, Qdrant 는 엉뚱한 질문에도 가장 비슷한 문서를 항상 하나 돌려준다. 세종대왕 질문에도 리뷰 문서가 1등으로 나오는 이유다. 그래서 점수로 걸러내는 기준을 찾아봤고, 완전히 무관한 질문(0.55~0.62)은 0.65 정도를 기준으로 하면 확실히 걸러진다. 하지만 "해외 배송도 되나요?" 처럼 쇼핑몰 용어가 들어 있는데 문서에는 없는 질문(0.65~0.70)은 정상 질문(0.72~)과 0.02 밖에 차이가 안 나서 점수로는 못 가른다. 이 구간은 점수가 아니라 프롬프트 규칙이 맡아야 한다. 에이전트 쪽은 답변에 문서에만 있는 값(왕복 배송비 고객 부담, 30일, 5만 원, 100만 원)이 나와서 문서를 읽고 답한다는 것이 확인됐다. 모델 호출이 2번인 것은 첫 호출에서 검색이 필요하다고 결정하고, 검색 결과를 받은 두 번째 호출에서 답을 쓰기 때문이다. 강제실패 케이스가 처음에 FAIL 이었던 것은 에이전트 문제가 아니라 테스트 문구 문제였다.

무관한 질문에는 어떻게 답하는지는 그 시점까지 확인한 적이 없었다. `score_noise` 는 점수만 쟀고 모델을 부르지 않았으며, `agent_e2e` 에는 무관한 질문이 없었다. 코드를 보면 `/rag/ask` 는 `RAG_RULE` 이 있어서 문서에 없으면 없다고 답하지만, 에이전트에는 시스템 프롬프트가 없어서 일반 상식으로 답할 수 있을 것으로 예상했다. 직접 물어보니 "세종대왕이 누구야?" 와 "점심 메뉴 추천해줘" 모두 도구를 부르지 않고 길게 답했고, 예상이 맞았다. 이건 `score_threshold` 로 해결되지 않는다. threshold 는 검색이 일어난 뒤에 작동하는데, 이 경우는 모델이 검색을 아예 하지 않기 때문이다.

그래서 `agent_node` 에 시스템 프롬프트를 추가했다. 쇼핑몰 상담원 역할, 정책 질문은 검색 결과만 근거로 답하기, 시간은 도구로 확인, 쇼핑몰과 무관한 질문은 거절 안내라는 내용이다. 기존 호출은 `[OLD]` 주석으로 남겼고, `agent_e2e` 에는 범위 밖 질문 2개를 추가했다. 프롬프트는 강제가 아니라 유도라서 100% 막지는 못한다. 적용 후 전체를 다시 돌려 보니 범위 밖 질문 2개는 거절 안내로 바뀌었고 기존 케이스는 모두 통과했다(11 / 11, 아래 재실행 결과). 거절은 검색도 긴 생성도 없어서 1초대로 끝나고, 문서에 없는 적립률 질문도 VIP 이야기를 덧붙이지 않고 고객센터 안내로 끝나게 됐다.
