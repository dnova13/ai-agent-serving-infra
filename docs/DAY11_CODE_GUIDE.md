**전체 목적:** (1) 범위 밖 질문을 막는 시스템 프롬프트가 에이전트에 어떻게 붙는지, (2) 에이전트를 서버 없이 통째로 시험하는 스크립트가 무엇을 판정하는지, (3) 검색 점수의 바닥값을 재는 스크립트가 무엇을 비교하는지 따라간다.


## 1. 전체 흐름

```
[바뀐 코드]  agent_graph.py 의 agent_node
   모델 호출 직전에 SystemMessage(SYSTEM_PROMPT) 를 messages 맨 앞에 붙인다 (state 에는 넣지 않음)

[새 스크립트 1]  python -m app.checks.agent_e2e
   CASES 의 질문마다 AGENT_GRAPH.invoke → 호출된 도구, 답에 든 값, 시간 → PASS / FAIL / INFO

[새 스크립트 2]  python -m app.experiments.score_noise
   질문 3묶음(관련 / 쇼핑몰 질문이지만 문서 없음 / 완전 무관)의 top-1 점수를 재서 min, max 비교
```

| 단계 | 하는 일                          | 파일                                              | 함수                              |
| ---- | -------------------------------- | ------------------------------------------------- | --------------------------------- |
| A    | 시스템 프롬프트 붙이기           | `d2-ai-python/app/services/agent_graph.py`        | `SYSTEM_PROMPT`, `agent_node`     |
| B    | 에이전트 통합 테스트             | `d2-ai-python/app/checks/agent_e2e.py`          | `run_case`, `judge`, `main`       |
| C    | 점수 바닥값 측정                 | `d2-ai-python/app/experiments/score_noise.py`        | `section`, `main`                 |


## 2. 주요 코드

### 2-1. 시스템 프롬프트 (`agent_graph.py`)

```python
SYSTEM_PROMPT = (
    "당신은 쇼핑몰 고객센터 상담원입니다. 한국어로 간결하게 답하세요.\n"
    "- 환불, 배송, ... 질문은 반드시 search_vector_db 로 검색하고, 검색된 문서에 있는 내용만 근거로 답하세요. 문서에 없으면 모른다고 답하고 ...\n"
    "- 현재 날짜나 시간은 get_current_time 으로 확인하세요.\n"
    "- 인사 같은 가벼운 대화에는 짧게 답하세요.\n"
    "- 쇼핑몰 상담과 무관한 질문(역사, 요리, 투자, 코딩 등)에는 답하지 말고 '...'라고 안내하세요."
)

response = model_with_tools.invoke([SystemMessage(content=SYSTEM_PROMPT)] + state["messages"])
```

| 부분                         | 설명                                                                                                                                  |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 왜 필요했나                  | 코드 주석: 이게 없으면 모델이 "검색이 필요 없다"고 판단한 질문(세종대왕, 점심 메뉴 등)에 일반 상식으로 답해 버린다                      |
| state 에 안 넣고 호출 직전에만 붙임 | `state["messages"]` 에는 시스템 메시지가 쌓이지 않는다. 노드가 불릴 때마다 맨 앞에 붙이므로 대화 기록이 오염되지 않는다             |
| 한계                         | 코드 주석: 프롬프트는 강제가 아니라 유도라서 100% 보장은 아니다                                                                          |

### 2-2. 에이전트 통합 테스트 (`agent_e2e.py`)

```python
CASES = [("환불-변심", "단순 변심으로 환불하면 배송비는 누가 내요?", "search_vector_db", ["왕복", "고객"], "refund-001"), ...]

state = {"messages": [HumanMessage(question)], "provider": provider, "retry_count": 0, "pending_tool_calls": []}
out = AGENT_GRAPH.invoke(state)
tools = used_tools(out["messages"])            # 대화 기록에서 모델이 요청한 도구 이름을 순서대로
```

| 판정 규칙 (`judge`)           | 설명                                                                                                                                   |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 도구 선택                     | 기대 도구가 있으면 그 도구가 호출됐는가, 기대 도구가 `None` 이면 도구를 하나도 안 불렀는가                                             |
| 문서 반영                     | 답에 "DB 문서에만 있는 값"(예: `30일`, `3,000`, `100만`) 중 하나가 들어 있는가. 값 목록이 비면 검사하지 않는다                           |
| `PASS` / `FAIL` / `INFO`      | 에러가 나면 `FAIL`, 비고가 `INFO` 로 시작하는 케이스(문서에 없는 질문)는 합격 여부 없이 `INFO`. 마지막 `PASS n / m` 은 `INFO` 를 뺀 수 |
| 케이스 사이 `--sleep`         | 질문 하나가 임베딩과 채팅 호출을 여러 번 일으켜서 무료 한도(429)를 피하려고 기본 5초 쉰다                                               |

범위 밖 질문 케이스(`세종대왕이 누구야?`, `점심 메뉴 추천해줘`)는 기대 도구 `None` 에 답에 `고객센터`, `쇼핑몰`, `어렵` 중 하나가 있어야 통과한다. `강제실패` 케이스는 Day 6 의 재시도(`MAX_RETRIES`)와 포기 문구(`죄송`)를 확인한다. 코드 주석에 따르면 질문 뒤에 괄호로 붙이면 모델이 검색어에서 빼 버려 실패가 안 일어났고(Day 11 첫 실행에서 FAIL), 그래서 검색어 자체가 `강제실패` 가 되도록 질문한다. 그래도 모델 판단에 따라 달라질 수 있다.

### 2-3. 점수 바닥값 (`score_noise.py`)

```python
rel = section("관련 질문", RELEVANT)
dom = section("쇼핑몰 질문, 문서에 없음", IN_DOMAIN_NO_DOC)
off = section("완전 무관", OFF_TOPIC)
gap = min(rel) - max(off)           # 관련 질문의 최저 점수 - 무관 질문의 최고 점수
```

| 부분                         | 설명                                                                                                                                  |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 왜 재나                      | Day 9 에서 정답 점수(0.71~0.82)와 오답 점수가 겹쳤다. 무관 질문의 점수가 그 구간과 떨어져 있으면 `score_threshold` 를 정할 수 있다      |
| `gap`                        | 양수이고 0.03 보다 크면 "threshold 로 구분 가능", 아니면 "구간이 겹쳐 threshold 만으로는 구분 어려움"이라고 출력한다                      |
| `top1`                       | `search(q, limit=1)` 의 1위 한 건의 점수만 쓴다                                                                                          |
| `time.sleep(0.5)`            | 질문마다 임베딩 API 를 한 번씩 부르므로 한도 완화                                                                                        |


## 3. 결과를 읽는 순서

1. `agent_e2e` 마지막의 `PASS n / m` 과, `FAIL` 이 있으면 그 케이스의 `tools=[...]` 와 `answer` 를 본다.
2. 범위 밖 질문이 도구 없이 안내 문구로 끝났는가, `문서없음` 케이스의 답이 수치를 지어내지 않았는가(`INFO`, 눈으로 판단).
3. `score_noise` 마지막의 `관련 min`, `문서없음 max`, `무관 max`, `gap`.
