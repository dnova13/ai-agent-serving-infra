# Day6 테스트 로그 정리

## 테스트 목적
`retry_count` State 필드가 실제로 그래프 흐름을 제어하는지 검증.
(도구 실행 실패 → 재시도 → 한계 초과 시 포기(give_up)까지 전 과정)

---

## 테스트 1 — 도구 분기 정확도 (Conditional Edge)

| 질문 | 기대 경로 | 결과 (Gemini) |
|---|---|---|
| "환불 정책이 어떻게 되나요?" | `search_vector_db` 호출 | ✅ 정확히 호출, 7일 이내 환불 정보 반영 |
| "지금 몇 시야?" | `get_current_time` 호출 | ✅ 정확히 호출, 실제 시각 반환 |
| "안녕!" | 도구 없이 바로 답변 | ✅ 도구 호출 없이 END로 직행 |

**결론**: 도구 2개 이상일 때도 모델이 질문에 맞는 도구를 정확히 골라 쓴다.

---

## 테스트 2 — retry_count / give_up (1차 시도, 실패)

**질문**: "환불 정책 강제실패 테스트해줘"

**결과**: 도구가 아예 호출되지 않음. 모델이 "강제실패"라는 단어를
"네거티브 테스트 개념 설명해달라"는 요청으로 오해하고, 테스트 시나리오
체크리스트를 나열하는 답변을 내놓음.

**원인**: 질문 문구가 자연스럽지 않아서, 모델이 검색 대상이 아니라
"이 개념을 설명해달라"는 메타 질문으로 해석함.

**조치**: 질문 문구를 자연스러운 검색 요청 형태로 변경
→ `"환불 정책이 어떻게 되나요? (검색 키워드: 강제실패)"`

---

## 테스트 3 — retry_count / give_up (2차 시도, 도구는 호출됐으나 로직 미검증)

**질문**: "환불 정책이 어떻게 되나요? (검색 키워드: 강제실패)"

**결과**: 도구가 호출되어 의도한 대로 예외가 발생했고, 최종적으로
"죄송합니다. 현재 환불 정책 정보를 확인하는 과정에서 일시적인 시스템
오류가 발생했습니다..." 라는 답변이 나옴.

**문제**: 이 문구가 `give_up_node`에 하드코딩해둔 문구
(`"죄송합니다, 2번 시도했지만..."`)와 **일치하지 않음** → give_up_node를
실제로 거쳤는지 의심스러움.

**조치**: `after_tools_router`, `give_up_node`에 `[DEBUG]` print 로그 추가
후 재실행.

**로그 결과**:
```
>>> [DEBUG] after_tools_router 호출됨: failed=True, retry_count=1
```
1번만 찍히고 `give_up_node 진입함` 로그는 안 찍힘.

**원인 확정**: 기존 구현이 실패 시 `agent` 노드로 돌려보내 모델이 알아서
재시도하길 기대했는데, **모델이 1번 실패 후 재시도 없이 스스로 사과
답변을 만들어버림.** `retry_count`가 1에서 멈추고 `give_up`까지 못 감.

---

## 테스트 4 — 로직 재설계 후 최종 검증 (성공)

**변경 내용**:
- State에 `pending_tool_calls` 필드 추가 (재시도 시 원본 도구 요청 보존용)
- `tool_node`가 `state["messages"][-1]` 대신 `state["pending_tool_calls"]`를 실행 대상으로 삼도록 변경
- `after_tools_router`: 실패 시 `agent`가 아니라 `tools`로 직접 재시도 (모델 판단 배제, 그래프가 결정적으로 재실행)
- 그래프에 `tools → tools` 자기 자신으로 돌아가는 엣지 추가

**질문**: "환불 정책이 어떻게 되나요? (검색 키워드: 강제실패)"

**로그 결과**:
```
>>> [DEBUG] after_tools_router 호출됨: failed=True, retry_count=1
>>> [DEBUG] after_tools_router 호출됨: failed=True, retry_count=2
>>> [DEBUG] give_up_node 진입함 (retry_count 한계 도달, 강제 종료 처리)
```

**최종 답변**:
```
죄송합니다, 2번 시도했지만 요청을 처리하지 못했습니다. 잠시 후 다시 시도해주시거나 다른 방식으로 질문해주세요.
```

`give_up_node`에 하드코딩한 문구와 **정확히 일치**. 모델이 개입할 여지 없이
그래프가 설계한 대로 정확히 실행됨을 확인.

## 부수적으로 겪은 이슈 — Gemini API 쿼터

- 테스트 반복 중 `gemini-3.6-flash`의 **일일 무료 요청 한도(20건)** 소진 → 429 RESOURCE_EXHAUSTED
- 재시도 로직 자체가 실패 시 모델을 여러 번 호출하는 구조라서, 한 번의 강제실패 테스트가
  내부적으로 여러 번의 API 호출을 유발해 쿼터를 빠르게 소모함
- **조치**: 무료 티어 한도가 더 넉넉한 `gemini-3.1-flash-lite`로 모델 교체
- **참고**: Google Cloud 결제 계정만 연결하면 즉시 Tier 1로 전환되어 한도가 100~200배 증가.
  최소 결제 금액이나 대기 기간 없음. 5주 차 k6 부하 테스트 때는 이 방식이 필수적일 것으로 예상.

## 최종 결론

| 검증 항목 | 상태 |
|---|---|
| 도구 다중 분기 (Conditional Edge) | ✅ 검증 완료 |
| retry_count 증가 로직 | ✅ 검증 완료 (1→2) |
| give_up 분기 및 실행 | ✅ 검증 완료 (로그 + 하드코딩 문구 일치로 확인) |
| 결정적 재시도(모델 판단 배제) | ✅ 적용 완료 |
| Gemini 무료 티어 쿼터 이슈 | ✅ 모델 교체로 우회, Tier 1 전환 방법 확인해둠 |

[DEBUG] print 로그는 2주 차 이후에도 디버깅에 유용할 수 있어 **제거하지 않고 유지**하기로 결정.
